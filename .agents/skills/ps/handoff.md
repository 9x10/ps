# Hand off an audited run

Use this playbook before returning control after unattended work, including a run stopped by a blocker, or when the user asks for an audited handoff. An explicit handoff request is read-only. Inspect existing evidence and permitted live readbacks. Handle an immediate pause or stop through the [hold rules](resume.md#pause-at-a-safe-boundary) without waiting for an audit. A read-only audit of held work stays within the allowed scope and leaves the hold active. Dispatch the reviewer only if the current scope permits it.

## Audit the run

1. Pin the named run, requested scope, review cutoff, latest [complete checkpoint](resume.md#resume-from-a-fresh-session), and relevant revisions and artifacts. Include earlier checkpoints across sessions and flag incomplete entries or external actions that need live reconciliation. Give an independent reviewer the [shared brief](worker.md#worker-brief) with read-only scope and the raw record, scoped transcript where available, artifact links, and applicable user instructions. Use a fresh reviewer who neither did the work nor made its decisions. Prefer a different model family when available and authorized.
2. Have the reviewer check material decisions and claimed outcomes against the underlying evidence. Check the finish condition, required slices, proof on the tested revisions, scope of approvals, holds, and outstanding actions. Look for missing decisions, skipped proof, stale or contradictory results, and scope violations. Read only this run's evidence. Return the exact checkpoint or artifact for each flag, what it establishes, what is still unverified, and who can act on it.
3. Verify material flags against the evidence. Before sending, re-read the live state and authorization behind the finish condition, material audit conclusions, and each proposed decision, even if no decision is pending. If material state moves, refresh the affected audit before relying on it. If independence, evidence, or live reconciliation is missing, say what could not be confirmed. A coordinator's own check leaves independent audit status incomplete. The coordinator records reviewer, scope, evidence, and outcome in the existing record when writing is allowed. For a read-only request, keep those details in the reviewer report and surface only what affects the handoff.

## Return only the user's decisions

1. Within the current handoff scope, include each still-open call that only the user can make for the requested endpoint or that they explicitly asked you to bring back. Check earlier requests and approvals so an answered or superseded call stays off the list. Include product choices evidence cannot settle, approvals actually needed, or access only the user can grant. Ask for approval when its prerequisite evidence is current. If the missing step belongs to an agent, keep it with the agent. Keep agent-owned repairs, routine updates, and outstanding automated checks in the run record. An audit flag becomes a decision only if it needs the user's action now.
2. For each decision, name the affected PR or scope and ask for a specific choice. Give your recommendation and why, the evidence that supports it, and the material risks of the viable options. State important unknowns and what the decision unlocks. Make each item usable without opening its links. Group items only when the authorization or choice is shared and its scope is clear.
3. When none qualify, say “No decisions needed” if the audit supports it, or “No confirmed decisions” if the audit is incomplete. Briefly disclose any material audit limitation or scope breach. Link the run record for context. Use the existing [required-check](verification.md#protect-required-checks), [live rerun](adversarial-review.md#independent-live-rerun), [merge](orchestration.md#merge-gate), and [hold release](resume.md#release-held-work) rules for any later action.
