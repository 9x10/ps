# Project

`ps` is a starter for agent-led engineering in the Codex CLI. Use `$ps` to select a task playbook. Agents fill in the facts below from the brief, code, and CI, and update them when the project changes.

- **Purpose and users** — Unset
- **Real entry points and ownership** — Unset
- **Behavior and contracts to preserve** — Unset
- **High-risk changes** — Unset

## Verification

Record repeatable commands or steps and what should happen. Start with one real user flow using test data. When the project has several important flows, index them in existing verification docs or `VERIFICATION.md` and link to the map here. Use `Unset` for unknowns and `N/A` with a reason for checks that do not apply.

| Check | Command or steps | Expected result | When required |
| --- | --- | --- | --- |
| Setup and test data | Unset | Unset | When needed for a required check |
| Real smoke check | Unset | Unset | Changes to observable behavior |
| Tests, build, lint, or CI | Unset | Unset | As defined by project policy |
